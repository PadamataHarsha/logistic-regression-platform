# Logistic Regression Intelligence Platform

A small FastAPI application built around the existing advertising Logistic Regression project. It keeps the original five model inputs and preprocessing pipeline, trains from the real `advertising.csv`, saves model artifacts, and serves predictions and evaluation pages from one Python process.

> **Educational use only.** Model estimates are not guaranteed real-world outcomes and should not be used as the sole basis for decisions about people.

## Features

- Session-based login with three roles and Argon2 password hashes.
- Role-aware dashboard, prediction form, performance report, data insights, about, and profile pages.
- Exact feature order and the fitted `StandardScaler` + Logistic Regression pipeline from the original script.
- Real holdout metrics, confusion matrix, class distribution, descriptive statistics, and feature charts.
- Local CSS and JavaScript; no frontend framework or CDN is required.
- Health endpoint and Railway configuration.

## Dataset and model

The project uses the supplied 1,000-row `advertising.csv`; it does not make synthetic training records. The target is `Clicked on Ad`. For that target, class `0` is shown as **Unlikely to Click**, and class `1` as **Likely to Click**.

The inputs, in the exact model order, are:

1. `Daily Time Spent on Site`
2. `Age`
3. `Area Income`
4. `Daily Internet Usage`
5. `Male` (0 or 1, using the dataset encoding)

Training retains the original stratified 70/30 train/test split (`random_state=42`), `StandardScaler`, and `LogisticRegression(max_iter=1000, random_state=42)`. The saved model is a single sklearn `Pipeline`; the server loads it once at startup and never retrains in response to a page request.

The current saved model evaluated at **97.7% accuracy**, **98.6% precision**, **96.7% recall**, and **97.6% F1** on 300 held-out rows. These are dataset-specific metrics, not a promise of future performance. Run the training command again after changing the CSV.

## Local installation

Python 3.12 is used for Codespaces and Railway. From a terminal:

```bash
cd lRP
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

On Windows PowerShell, activate with `.venv\Scripts\Activate.ps1` instead. If you use a different terminal, activate the virtual environment before installing packages or starting the server.

Create a local environment file and replace the session secret with a generated value:

```bash
cp .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

Put the generated value in `.env` as `SESSION_SECRET_KEY`. `.env` is ignored by Git. The application has safe development-only demo defaults if you do not create `.env`; never use those defaults in production.

Train the real dataset and save the model and charts:

```bash
python train_model.py
```

Then start the application:

```bash
python -m uvicorn main:app --host 0.0.0.0 --port 8000
```

Open `http://localhost:8000/login`. In Codespaces, open the forwarded port 8000 from the **Ports** panel; the forwarded address is generated by Codespaces and is not hard-coded in the app. Use `Ctrl+C` in the terminal to stop the server.

If the saved model is absent, the server still starts and `/health` reports `degraded`; prediction pages show the instruction to run `python train_model.py`.

## Demo login accounts

These credentials are for local demonstration only. The application hashes each password with Argon2 when it starts. The passwords are not placed in HTML, JavaScript, or browser storage.

| Role | Username | Development-only password |
| --- | --- | --- |
| Admin | `admin` | `AdminDemo123!` |
| Analyst | `analyst` | `AnalystDemo123!` |
| Viewer | `viewer` | `ViewerDemo123!` |

Set a unique password for every account before deployment. When `APP_ENV=production`, startup requires a `SESSION_SECRET_KEY` of at least 32 characters and all six account username/password variables. Production passwords must be at least 12 characters and cannot equal the development demo passwords; development fallbacks are not accepted.

## Routes and access

| Route | Access | Purpose |
| --- | --- | --- |
| `/` | Public | Redirect to login or dashboard |
| `/login` | Public | Sign in |
| `/logout` | Signed-in user | Clear the session (POST with CSRF token) |
| `/dashboard` | All roles | Dataset, model metrics, recent session predictions |
| `/prediction` | All roles | Validate inputs and estimate class probabilities |
| `/api/predict` | All roles | Authenticated JSON prediction API; send the session CSRF token in `X-CSRF-Token` |
| `/evaluation` | Admin, Analyst | Holdout report, confusion matrix, and coefficients |
| `/analytics` | Admin, Analyst | Model metrics, confusion matrix, and coefficients |
| `/performance` | Admin, Analyst | Holdout report, confusion matrix, coefficients |
| `/insights` | Admin, Analyst | Aggregate dataset information and charts |
| `/about` | All roles | Model explanation and limitations |
| `/profile` | All roles | Safe account and session details |
| `/health` | Public | Railway health check JSON |
| `/api/health` | Public | Health JSON alias |

Viewer accounts receive a rendered 403 page on evaluation routes. Unauthenticated users are redirected to `/login`. Session cookies are signed, HttpOnly, SameSite=Lax, and use Secure cookies when `APP_ENV=production`; login and logout forms include CSRF tokens. By default, the cookie lasts for the browser session. Selecting Remember me gives it a 30-day max-age.

## Download and upload to GitHub manually

The complete archive is prepared at:

```text
/workspaces/codespaces-jupyter/logistic-regression-platform-ready.zip
```

To publish without using `git push`:

1. Download `logistic-regression-platform-ready.zip` from the Codespaces file explorer or its download action.
2. Extract the ZIP on your computer.
3. Create a new empty repository on GitHub.
4. In that repository, select **Add file** and then **Upload files**.
5. Upload the extracted project files and folders, not just the ZIP file.
6. Confirm `main.py`, `requirements.txt`, `templates/`, `static/`, `models/`, `Procfile`, and `railway.json` are visible at the repository root.
7. Commit the uploaded files to the `main` branch.
8. Connect that repository to Railway using the steps below.

Do not upload only the ZIP as the repository's sole file; GitHub and Railway need the extracted project structure.

## Deploy to Railway

1. Create a Railway project and choose **Deploy from GitHub Repo**.
2. Select the repository you uploaded.
3. Set the root directory to `.` when the project files are at the repository root. If you uploaded a parent folder, set the root to that folder containing `main.py` and `requirements.txt`.
4. Railway can install `requirements.txt` automatically. If a build command is required, use `python -m pip install -r requirements.txt`.
5. Use this start command if Railway does not detect the `Procfile`:

   ```text
   uvicorn main:app --host 0.0.0.0 --port $PORT
   ```

6. Set the health-check path to `/health`.
7. Add these Railway variables. Generate `SESSION_SECRET_KEY` with `python -c "import secrets; print(secrets.token_urlsafe(48))"`; use unique, strong passwords for each account.

   ```text
   APP_ENV=production
   SESSION_SECRET_KEY=<generated-long-random-value>
   ADMIN_USERNAME=<your-admin-name>
   ADMIN_PASSWORD=<unique-strong-password>
   ANALYST_USERNAME=<your-analyst-name>
   ANALYST_PASSWORD=<unique-strong-password>
   VIEWER_USERNAME=<your-viewer-name>
   VIEWER_PASSWORD=<unique-strong-password>
   ```

8. Deploy and read the build and deployment logs if startup fails.
9. In Railway networking/settings, generate a public domain for the service.
10. Open the generated domain at `/health`, `/login`, and then the dashboard after signing in.

The model artifact and metadata are included in the project. Keep `models/trained_model.joblib` and `models/model_metadata.json` in the repository so Railway can load the trained model. This application does not use SQLite or another database; prediction history is limited to the signed browser session and is not durable storage.

## Troubleshooting

- **Missing dependency:** activate the intended Python environment, then run `python -m pip install -r requirements.txt` again.
- **Wrong project root:** run commands from the folder containing `main.py`, `train_model.py`, and `requirements.txt`. On Railway that folder is the service root directory.
- **Model missing:** run `python train_model.py` locally and confirm `models/trained_model.joblib` and `models/model_metadata.json` exist. Include both in the GitHub repository.
- **Railway `PORT` error:** keep `$PORT` in the Procfile/start command. Do not set a fixed production port or add a manually defined `PORT` variable; Railway provides it.
- **Production configuration error:** set `APP_ENV=production`, a long random `SESSION_SECRET_KEY`, and all three usernames and passwords in Railway Variables.
- **Model version warning:** the project pins scikit-learn to the version used to serialize the included model. Retrain with `python train_model.py` after intentionally changing that version.

## Security and limitations

This is a learning and demonstration application, not a hardened identity platform. Demo account defaults are public by design; replace them before deployment. Configure all credentials as host environment variables, keep `.env` private, and use HTTPS. Authentication has no database, account recovery, rate limiting, or centralized session revocation. Signed browser-session cookies are cleared on logout; selecting Remember me makes the cookie valid for 30 days. The included dataset and model may reflect collection bias, and model associations do not establish causation. Do not use the estimates as guaranteed outcomes or as the sole basis for decisions about people.
